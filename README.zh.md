# tell-me-tick-me

Tell me what to do, and tick me off when it's done.

一个 **AI-native 的桌面待办应用**,里面住着一位 AI 秘书 **Amy**(名字来自中文谐音"A秘"= AI 秘书)。

待办窗口像 QQ 一样**吸附在屏幕边缘**,鼠标碰到滑出、离开收回,**不占屏幕使用空间**。你可以定期跟 Amy 聊聊最近要做的事,她会帮你**拆解、排序、在 deadline 撞车的时候出主意**;她有自己的**长期记忆**,所以能理解你的长期安排和项目进度。如果你给她一些联网搜索,邮件访问和日历写入等权限,她能更好地理解和协助你的工作和生活。完成的每件待办任务,在勾掉之后会自动归档进当天的日记,方便整理和回顾工作进度。

另外,推荐把 Amy 接入 **Discord**(或其他任何聊天软件),这样手机上也能随时给它发消息。每天早上 Amy 主动发消息**提醒待办**,晚上**来复盘和道晚安**,深夜没回音还会**喊你早点睡**;接上 **Apple Watch** 后,她还会按你**昨晚实际入睡的时间**和交通时刻表,**自动**在手机上**创建起床闹钟**。

## 🌱 为什么做这个

作为博士生,我每天的日程自由度很高,也非常依赖自我管理。每天要做什么,取决于论文进度、实验状态、项目 deadline,还有临时冒出来的新任务,**很难用固定列表把每天过得标准化**。

所以我想要做一个工具,帮我把"今天该做什么"安排清楚:整理正在推进的项目,区分**今日、本周、本月和长期**,复盘已经完成的部分,少一点"想到什么就先做什么"的随意。列出没做完的事只是基本功,它更要帮我看清:**现在最该推进的是什么**,哪些事看起来急其实可以缓,哪些值得投入更多,哪些做到够好就行。

## 🧠 任务太多的时候,和 AI 商量

几个项目的 deadline 挤在同一段时间的事,总会发生。人在任务突然堆起来的时候**很容易 panic**:不知道先做哪个,不知道从哪下手,甚至因为每件都想做好,反而迟迟动不了。

这种时候我可以直接和 Amy 聊:最近有哪些任务,卡在哪里,哪些有前置条件,时间不够时精力怎么分。排序之外,她还参与更实际的判断:**哪些事做到 60 分就够,哪些应该做到 80 分,哪些值得全力以赴**,在能力范围内做到尽可能好。目标是在任务密集、精力有限的时候**做出清醒、现实的选择**,而不是把所有任务都标成"重要"。

## ✨ 和普通待办软件有什么不同

成熟的待办工具已经很多,这个项目的区别在于:**AI 就是工作流的核心**,而且这件事落在几条实际的设计上:

- **待办就是一份纯文本 markdown**(todo.md):AI 直接读它,数据永远在自己手里,不用把生活塞进表单
- **Amy 看得到项目背景和每日归档**:能结合真实进度拆任务、排优先级、帮复盘
- **Amy 只提建议,落盘必须你确认**(桌面点卡片,手机回「确认」):新增/挪动/移除,她没有直接改动待办的权力
- **Amy 有自己的记忆文件**:会逐渐形成对你工作方式和长期目标的理解

## 👋 这个项目也许也适合你

如果你和我一样,脑袋里经常冒出各种各样的想法,也很容易同时开始多个项目,但在真正执行时,却常常难以从一而终:做着做着就偏离了最初的目标,忘记项目进行到了哪里,也失去了对整体进度的把握。那么这个项目或许也会适合你。

很多时候,**想法和努力都不缺**,卡住的是:

- 同时进行的事情太多;
- 新的想法不断出现;
- 项目的下一步不够明确;
- 任务做了一半,却没有留下清楚的进度记录;
- 注意力被新的问题吸引,渐渐 lose track;
- 过了一段时间再回来时,已经很难快速接上之前的思路。

我希望这个工具在记录"今天要做什么"之外,还能**保留工作的上下文**:这个任务属于哪个项目、为什么要做、目前进行到了哪里、下一步是什么,以及它与其他任务之间有什么关系。

这样,**即使中途被别的事情打断,也能更容易地回到原来的轨道上**。

## 🧪 它来自一套已经实际使用了半年多的工作流

在开始开发这个独立项目之前,我已经**持续使用 AI 帮助自己管理日程、梳理任务、记录进度和讨论工作策略半年多**了。

在这段时间里,我会和 AI 一起:

- 整理当天和近期的任务;
- 判断不同项目的优先级;
- 分析任务为什么被卡住;
- 把模糊的目标拆成可以执行的下一步;
- 记录每个项目已经完成的内容;
- 在多个 deadline 冲突时讨论如何取舍;
- 定期回顾进度,避免项目在忙碌中悄悄失踪。

这套工作方式明显提高了我的工作效率。更重要的是,它**减少了我在任务很多时反复思考"现在到底该做什么"的负担**,也让我更容易重新进入一个暂时中断的项目。

不过在过去,这些交互只存在于我自己的工作区里。任务文件、项目记录、AI 对话和工作规则都是围绕我的个人环境逐渐形成的,并不是一个可以让其他人直接安装和使用的产品。

现在,我正在根据自己与 AI 的真实交互习惯,以及现有工作区的设计,**把这套工作流整理、抽象并包装成一个可以独立运行的开源工具**。

## 🚀 跑起来

要求:macOS(悬浮窗为 Mac 原生;网页部分任何系统都能跑)、Python 3.10+、可选 Xcode 命令行工具(编译悬浮壳)。

```bash
git clone https://github.com/cyresearch/tell-me-tick-me
cd tell-me-tick-me
./run.sh
# 浏览器打开 http://127.0.0.1:8765
```

首跑会自动生成一份示例 todo(`data/todo.md`),**开箱就能勾**。想用悬浮小窗:

```bash
./shell/build.sh      # 编译一次
./shell/TellMeTickMe  # 吸附在屏幕右缘, 鼠标碰边滑出
```

## 🔌 接入你自己的 LLM(Amy 上岗)

第一次打开对话面板,会看到设置向导,**三条通道选一条**:

| 通道 | 适合谁 | 说明 |
|---|---|---|
| **Claude Code** | 已订阅 Claude 的人 | 用你自己的订阅,第一方合规;**功能最全**:Amy 能检索你指定的资料目录、自己维护记忆 |
| **Anthropic API** | 有 API key 的人 | key **只存在本机** `config/llm.json`,不经过任何第三方 |
| **Ollama** | 想零成本全离线的人 | 本地模型,**数据不出电脑** |

**不接 LLM 也完全可以用**:勾选、归档、编辑、磁吸窗口都不依赖 AI。本项目**不做任何"订阅搭车"式的第三方接入**,三条通道全是正规门。

💡 **建议搭配语音输入**:用系统听写或你惯用的语音输入法,对着输入框把最近的事**说**给 Amy 听。商量任务这种事,说话比打字快得多。

## 📱 把 Amy 装进手机:Discord 私聊(可选)

给 Amy 建一个 Discord bot,她就能住进你的手机:

- **私聊直达**:一对一 DM,不用建频道、不用 @;她只听你(按用户 ID 过滤)
- **和桌面同一个 Amy**:手机聊的和桌面聊的是同一份记忆、同一份历史;她给的待办建议,**回一句「确认」当场落盘**,人不在电脑前也能把事情定下来
- **主动来找你**:每天的晨报同时发到桌面和 DM,睡前的晚安和查岗也走这条线
- **在线绿点**:值班员带一条 gateway 心跳,Amy 的头像是亮着的

配置两样即可:bot token 和你的用户 ID(环境变量 `AMY_DISCORD_TOKEN` / `AMY_DISCORD_USER`),值班员是 `engine/amy_discord.py`。下一节的睡眠数据也经 Discord 频道传输,所以这一步是它的前置。

## ⏰ 通过睡眠监测智能设定起床闹钟: 闹钟不该在你还没睡着时,就已经被决定

往往计划 23:30 睡,按"睡够 8 小时"把闹钟定在 7:30。但躺下之后迟迟没有睡着,实际入睡比计划晚了一个钟头;第二天固定的闹钟照样响起,睡眠被悄悄压缩。想把闹钟往后推,又必须赶上公交、地铁、火车,或者开车前必须出门的时刻, 结果在睡眠时长、起床时间和出门时间之间反复心算。

这个项目里还写了一个**知道你昨晚几点真正睡着、明早几点必须出门**的智能闹钟功能。

Tell Me, Tick Me 会在夜间自动读取 Apple Watch 记录的实际睡眠数据,结合你的目标睡眠时长、交通时刻表(公交、地铁、火车,或开车必须出发的时间 - 你可以提前向 Amy 发送常坐班次的时刻表)和洗漱早餐的准备时长,计算出一个尽量保住休息、又不耽误出门的起床时刻,自动在 iPhone 上创建闹钟。**睡得越晚,它瞄准的班次就自动越晚**。

这套睡眠管理还包括:

- **23:30 Amy 来道晚安**:肯定你今天完成的事,提醒收尾;一直没回音的话 **00:30查岗**
- **晨报引用实测睡眠**(几点入睡、实睡多久、深睡多少)
- **豁免只要一句话**:跟 Amy 说"明早不用闹钟",那一个早晨就跳过,睡到自然醒

安心去睡。剩下的计算,交给 Amy。搭建步骤见 [docs/sleep-and-alarm.zh.md](docs/sleep-and-alarm.zh.md)(需要 Apple Watch 和 Discord bot,整套可选)。

## 🧩 搭配食用:让 Amy 从第一天就懂你

Amy 越了解你,建议就越准。我还做过一个 [chatgpt-memory-extraction](https://github.com/cyresearch/chatgpt-memory-extraction):把你几年的 ChatGPT 对话导出数据,整理成**结构化的个人记忆档案**(时间线、人物、主题)。把生成的档案目录写进 Amy 的人设里(资料地图那一节),用 Claude Code 通道时她就能按需检索:**你的来龙去脉、正在做的事、身边的人,她从第一天就知道**,不用每次从自我介绍开始。

## ⚙️ 配置(环境变量,都有默认值)

| 变量 | 默认 | 说明 |
|---|---|---|
| `DESK_TODO_FILE` | `data/todo.md` | 待办文件(可指向你自己的 markdown) |
| `DESK_DAILY_DIR` | `data/daily` | 每日归档目录 |
| `DESK_PORT` | `8765` | 端口 |
| `DESK_BIND` | `127.0.0.1` | 改 `0.0.0.0` 开放局域网(注意共享网络的风险) |
| `TMTM_CLAUDE_MODEL` | `opus` | Claude Code 通道的模型 |

Amy 的人设在 `config/secretary.example.md`,复制成 `config/secretary.md` 后按注释填上你自己的情况(它和 Amy 的记忆、你的 LLM 配置都**不进 git**)。

## 🛡 它怎么保护你的 todo.md

- **手动编辑永远优先**:每次操作前重读文件,以磁盘上的内容为准
- **写回只做行块级修改**,其余格式一字节不动
- 每天第一次写操作前**自动备份**到 `runtime/backups/`
- **所有操作可撤销**;AI 的每条建议都要人点确认
- 找不到条目(文件刚被别处编辑过)会拒绝操作并提示刷新,**不乱删**

这是一套**在长期使用中不断被检验和迭代**的个人工作系统,会持续开发和维护。
