# tell-me-tick-me

Tell me what to do, and tick me off when it's done.

デスクトップの隅に住む **AI ネイティブな todo アプリ**。中には AI 秘書の **Amy** がいます(名前は中国語の語呂合わせ「A秘」= AI 秘書から)。

todo ウィンドウは昔の QQ メッセンジャーみたいに**画面の端に吸い付き**、マウスが触れるとスッと出てきて、離れると引っ込みます。**画面のスペースを取りません**。最近やることを Amy に定期的に話しておくと、**タスクの分解、優先順位づけ、締め切りが重なったときの割り切り**を手伝ってくれます。彼女は自分の**長期記憶**を持っているので、あなたの長期的な予定やプロジェクトの進み具合を理解できます。ウェブ検索、メール参照、カレンダー書き込みなどの権限を渡せば、仕事と生活の理解と支援はさらに的確になります。チェックを入れた todo はその日の日記に自動でアーカイブされ、進捗の整理と振り返りに役立ちます。

あわせて、Amy を **Discord**(ほかのチャットアプリでも)につなぐのがおすすめ。スマホからいつでもメッセージを送れます。毎朝 Amy から**今日の todo のリマインド**が届き、夜は**一日の振り返りとおやすみの挨拶**、深夜に返事がないと**「早く寝て」と声をかけて**きます。**Apple Watch** をつなげば、**昨夜実際に眠った時刻**と交通の時刻表から、スマホの起床アラームを**自動で**作成します。

## 🌱 なぜ作ったか

博士課程の学生である私の毎日は、自由度が高いぶん自己管理がすべてです。その日にやることは論文の進捗、実験の状態、プロジェクトの締め切り、そして突然降ってくる新しいタスク次第。**決まりきったリストで毎日を標準化するのは無理がありました。**

だから「今日は何をすべきか」を整理してくれるツールが欲しかったのです。進行中のプロジェクトを整理し、**今日・今週・今月・長期**を区別し、終わったことを振り返り、「思いついた順にやる」を少しでも減らす。未完了のタスクを並べるのは基本のき。欲しいのは、**いま本当に進めるべきことは何か**、急ぎに見えて実は後回しでいいものはどれか、力を注ぐべきものと「ほどほどで十分」なものはどれか。それが見えるツールです。

## 🧠 タスクが多すぎるときは、AI と相談する

複数のプロジェクトの締め切りが同じ時期に重なることは、誰にでも起こります。タスクが急に積み上がると**人はパニックになりがち**です。どれから手をつけるか分からない、どこから始めればいいか分からない、全部ちゃんとやりたいばかりに、かえって何も始められない。

そんなとき私は Amy に直接相談します。最近のタスクは何か、どこで詰まっているか、前提条件があるものはどれか、時間が足りないときに力をどう配分するか。並べ替えの先で、**どれは 60 点で十分か、どれは 80 点まで持っていくべきか、どれに全力を注ぐ価値があるか**という、実際的な判断にまで踏み込みます。タスクが密集して余力がないときにこそ、すべてを「重要」にマークするのではなく、**冷静で現実的な選択をする**。それが目標です。

## ✨ 普通の todo アプリと何が違うか

成熟した todo アプリはすでにたくさんあります。このプロジェクトの違いは、**AI がワークフローの中心にある**こと。それは具体的な設計に表れています:

- **タスクはただの markdown ファイル**(todo.md):AI がそのまま読むので、データは常に自分の手元にあり、生活をフォームに押し込む必要がない
- **Amy はプロジェクトの背景と毎日のアーカイブを見られる**:実際の進捗に基づいてタスクを分解し、優先順位をつけ、振り返りを手伝う
- **Amy は提案するだけ。反映は必ずあなたのクリック**:追加・移動・削除の三種のカードはすべて確認待ち。彼女に todo を直接書き換える権限はない
- **Amy は自分の記憶ファイルを持つ**:あなたの働き方と長期的な目標への理解を、少しずつ育てていく

## 👋 こんな人に合うかもしれません

私と同じように、頭の中に次々アイデアが浮かんで、複数のプロジェクトを同時に始めてしまうけれど、いざ実行となると最後までやり通すのが難しい。やっているうちに当初の目標からずれて、プロジェクトがどこまで進んだか忘れて、全体の進捗もつかめなくなる。心当たりがあるなら、このプロジェクトはあなたにも合うかもしれません。

多くの場合、**アイデアも努力も足りています**。それでも:

- 同時進行のことが多すぎる;
- 新しいアイデアが次々に湧いてくる;
- プロジェクトの次の一歩が曖昧;
- タスクを半分やったのに、進捗の記録が残っていない;
- 注意が新しい問題に引っ張られて、だんだん見失っていく;
- しばらくして戻ってきたとき、前の思考にすぐ接続できない。

このツールには「今日やること」の記録にとどまらず、**仕事のコンテキストを保存する**役割を持たせたい。このタスクはどのプロジェクトのものか、なぜやるのか、いまどこまで進んでいるか、次は何か、他のタスクとどう関係するか。

そうすれば、**途中で別のことに中断されても、元の軌道に戻るのがずっと楽になります**。

## 🧪 半年以上、実際に使い続けてきたワークフローから生まれました

この独立したプロジェクトを作り始める前から、私は**半年以上、AI にスケジュール管理・タスク整理・進捗記録・仕事の戦略相談を手伝ってもらい続けて**きました。

その間、AI と一緒に:

- その日と直近のタスクを整理する;
- プロジェクト間の優先順位を判断する;
- タスクがなぜ詰まっているのかを分析する;
- 曖昧な目標を実行できる次の一歩に分解する;
- 各プロジェクトの完了内容を記録する;
- 複数の締め切りが衝突したとき、どう割り切るかを相談する;
- 定期的に進捗を振り返り、忙しさの中でプロジェクトがひっそり消えるのを防ぐ。

この働き方は明らかに効率を上げてくれました。それ以上に大きいのは、タスクが多いときに**「いま何をすべきか」を何度も考え直す負担が減った**こと、そして中断していたプロジェクトに再び入りやすくなったことです。

ただ、これまでこのやり取りは私の個人的なワークスペースの中にしか存在しませんでした。タスクファイル、プロジェクト記録、AI との会話、仕事のルール。すべて私の環境に合わせて育ったもので、他の人がそのままインストールして使える製品ではありませんでした。

いま私は、自分と AI の実際のやり取りの習慣と、既存のワークスペースの設計をもとに、**このワークフローを整理・抽象化して、単体で動くオープンソースツールに仕立てて**います。

## 🚀 動かす

必要なもの:macOS(フローティングウィンドウは Mac ネイティブ。Web 部分はどの OS でも動きます)、Python 3.10+、フローティングシェルをビルドするなら Xcode コマンドラインツール。

```bash
git clone https://github.com/cyresearch/tell-me-tick-me
cd tell-me-tick-me
./run.sh
# ブラウザで http://127.0.0.1:8765 を開く
```

初回起動でサンプルの todo(`data/todo.md`)が自動生成されるので、**その場でチェックを試せます**。フローティングウィンドウを使うなら:

```bash
./shell/build.sh      # 一度だけコンパイル
./shell/TellMeTickMe  # 画面右端に吸着、マウスを近づけるとスライドアウト
```

## 🔌 自分の LLM をつなぐ(Amy の出勤)

チャットパネルを初めて開くと設定ウィザードが出ます。**三つのチャンネルから一つ**選んでください:

| チャンネル | 向いている人 | 説明 |
|---|---|---|
| **Claude Code** | Claude のサブスク利用者 | 自分の契約をそのまま使う、正規の方法。**一番フル機能**:Amy が指定ディレクトリを検索でき、自分の記憶も管理できる |
| **Anthropic API** | API key を持つ人 | key は**この端末の** `config/llm.json` にだけ保存。第三者を経由しない |
| **Ollama** | コストゼロ・完全オフライン派 | ローカルモデルで、**データが PC の外に出ない** |

**LLM をつながなくても普通に使えます**:チェック、アーカイブ、編集、吸着ウィンドウに AI は不要です。このプロジェクトは**「サブスク相乗り」型の第三者接続を一切やりません**。三つのチャンネルはすべて正面玄関です。

💡 **音声入力との併用がおすすめ**:OS の音声入力や使い慣れた音声入力ソフトで、最近のことを Amy に**話しかけて**ください。タスクの相談は、打つより喋るほうがずっと速いです。

## 📱 ポケットの中の Amy:Discord DM(オプション)

Amy に Discord bot を用意すると、彼女はスマホに引っ越してきます:

- **DM で直接**:1 対 1 のダイレクトメッセージ。チャンネル作成も @ メンションも不要で、彼女はあなたにだけ応答します(ユーザー ID でフィルタ)
- **デスクトップと同じ Amy**:記憶も履歴も一つ。DM でもらった todo の提案は、デスクトップに戻って確認ボタンで反映
- **彼女の方から声をかけてくる**:毎日のブリーフィングはデスクトップと DM に同時に届き、おやすみの挨拶や夜ふかしチェックもこのラインで
- **オンラインの緑ドット**:デーモンが gateway のハートビートを保つので、アバターはオンライン表示

設定は 2 つだけ:bot のトークンとあなたのユーザー ID(環境変数 `AMY_DISCORD_TOKEN` / `AMY_DISCORD_USER`)。デーモンは `engine/amy_discord.py`。次のセクションの睡眠データも Discord チャンネル経由なので、このステップはその前提になります。

## ⏰ 睡眠トラッキングで起床アラームを賢くセット:アラームは、眠りにつく前に決まっているべきではない

たいてい 23:30 に寝るつもりで、8 時間睡眠を見込んで 7:30 にアラームをセットする。でも横になってもなかなか眠れず、入眠は予定より 1 時間遅れ、翌朝は固定のアラームが鳴って睡眠が静かに削られる。アラームを後ろへずらそうにも、バスや地下鉄、電車、車なら家を出るリミットがあり、結局、睡眠時間と起床時刻と出発時刻のあいだで暗算が続く。

このプロジェクトには、**昨夜実際に何時に眠ったか、今朝何時に出なければならないかを知っている**スマートアラーム機能も入っています。

Tell Me, Tick Me は Apple Watch が記録した実際の睡眠データを夜間に読み取り、目標睡眠時間、交通の時刻表(バス・地下鉄・電車、車なら出発リミット。よく乗る便の時刻表を事前に Amy に送っておけます)、身支度にかかる時間を組み合わせて、休息をできるだけ守りながら現実に間に合う起床時刻を計算し、iPhone のアラームを自動作成します。**眠るのが遅いほど、狙う便も自動で後ろへ。**

この睡眠ケア一式には、ほかにも:

- **23:30 に Amy がおやすみの挨拶**:今日終えたことを認めて、締めくくりを促す。返事がないままだと **00:30 に様子うかがい**
- **朝のブリーフィングは実測値**(入眠時刻・実睡眠・深い睡眠)で語る
- **免除はひとこと**:「明日の朝はアラーム要らない」と言えば、その朝だけスキップ

安心して眠ってください。計算は Amy に。セットアップは [docs/sleep-and-alarm.md](docs/sleep-and-alarm.md)(Apple Watch と Discord bot が必要。まるごとオプション)。

## 🧩 相性のいい相棒:初日から Amy に自分を知ってもらう

Amy はあなたを知るほど、提案が的確になります。私はもう一つ [chatgpt-memory-extraction](https://github.com/cyresearch/chatgpt-memory-extraction) というツールも作りました。何年分もの ChatGPT 会話のエクスポートデータを、**構造化された個人の記憶アーカイブ**(タイムライン・人物・トピック)に整理するものです。生成されたアーカイブのディレクトリを Amy のペルソナファイルに書いておけば、Claude Code チャンネルで彼女が必要に応じて検索できます。**あなたの来歴も、進行中の仕事も、周りの人も、初日から知っている**。毎回自己紹介からやり直す必要はもうありません。

## ⚙️ 設定(環境変数、すべてデフォルトあり)

| 変数 | デフォルト | 意味 |
|---|---|---|
| `DESK_TODO_FILE` | `data/todo.md` | todo ファイル(自分の markdown を指定可) |
| `DESK_DAILY_DIR` | `data/daily` | 日次アーカイブのディレクトリ |
| `DESK_PORT` | `8765` | ポート |
| `DESK_BIND` | `127.0.0.1` | `0.0.0.0` で LAN 公開(共有ネットワークでは注意) |
| `TMTM_CLAUDE_MODEL` | `opus` | Claude Code チャンネルのモデル |

Amy のペルソナは `config/secretary.example.md` にあります。`config/secretary.md` にコピーして、コメントに従って自分の状況を書き込んでください(ペルソナ、Amy の記憶、LLM 設定はすべて **git に入りません**)。

## 🛡 todo.md をどう守るか

- **手編集が常に優先**:操作のたびにファイルを読み直し、ディスク上の内容が正
- **書き込みは行ブロック単位の外科手術だけ**:それ以外はバイト単位でそのまま
- 毎日最初の書き込み前に `runtime/backups/` へ**自動バックアップ**
- **すべての操作が取り消し可能**。AI の提案は必ず人間のクリックを待つ
- 項目が見つからないとき(直前に別の場所で編集された等)は操作を拒否してリロードを促す。**推測で消したりしない**
